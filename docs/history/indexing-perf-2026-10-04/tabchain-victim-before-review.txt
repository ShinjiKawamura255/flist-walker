Causal conclusion
The fixed A->B->C->A trace can legitimately cancel low-priority generations under
the existing deterministic Active+Warm scheduler. The observed B6 had prior
Warm-eviction permission, Started with its own root/source, then Canceled with
false-current. All measured requests returned/released and sender/index/result
debt was zero. A8 and C7 finished with independent correct latest snapshots. B
retained independently correct seed3. The old benchmark all-tab latest-success
condition rejects that existing production behavior. A benchmark-only explicit
victim role is justified; production cancellation semantics must remain intact.

Accepted minimal design and conditions
1. Restrict victim roles to the fixed TabChain trace. Declare typed old-Warm
   candidates BEFORE the owned switch; select maximum owned measured planned
   allocation. Do not infer a role from an eventual cancellation or authorize it
   retroactively. Stage B->C targets old A; stage C->A targets old B.
2. Use a cfg(test), default-off, bounded scalar preemption event at the real
   mutation. Record after victim/return-false checks while the latest lock is held,
   immediately before latest.insert so the timestamp precedes worker visibility.
   Match exact victim ID/tab, prior latest ID, replacement0, active/current-Warm
   roles, and the exact owned queued/pending Active trigger request from that
   operation's allocation/deferred-activation graph. Current preferred Warm is
   the outgoing Active, not necessarily the old-Warm victim.
3. Require permission <= actual preemption <= Canceled offer <= body return.
   Every event must match one declared typed edge and interval. Missing cause,
   duplicate/unexplained event, wrong stage/victim/trigger, replacement nonzero,
   future/missing/wrong permission or overflow rejects. No payload/mailbox/Entry
   Arc retention or per-entry observer work; no production protocol/schedule fix.
4. Latest canceled B is accepted only as explicit LastGoodVictim with its actual
   admitted/Started root/source, Canceled false-current, nonzero emitted work,
   unchanged B10% checkpoint, physical return, release, route absence, no successor,
   and zero sender/GUI/result/deferred debt. Failed, closed-only, unsent, pre-start
   canceled or inferred map0 cannot establish this role.
5. A5->A8 retains its ordinary successor/revocation path. Required A8/C7 always
   need Finished and latest own generation/root/source/freshness/full oracle.
   Finished B requires generation6/full oracle, never the older seed fallback.
   Stable Active/Warm profiles retain their successful measured-B requirement.
   Maximum-planned identity remains intact; required-success and explicit-victim
   acceptance are typed separate decisions, not a generic latest-cancel exemption.
6. Verify seeded snapshots before t0 and retain only scalar root/source/request,
   count and membership/order signature witnesses, without an Arc pin. Tentative
   t2/t3 checks use the usual fast identity/count/debt gates plus exact victim
   cause and seed identity. Preserve candidate B scalar identity/generation and
   require them to match at final validation.
7. After tentative t3, without another GUI frame or input, validate the retained
   B seed's complete independent membership/kind/order/signature once. Do not
   scan100k every frame or add a new oracle cache. Reject corrupted seed even
   when all fast scalars are ready, before returning/emitting any correct:true
   sample. Final oracle failure is a failed sample, never a faster accepted row.
8. Raw evidence explicitly records victim/required roles, exact cause and actual
   emitted work. TabChain time is finite-lifecycle scenario completion, not proof
   that canceled B completed100k indexing or equal-work throughput improved.
   Historical comparisons retain identical initial settings/trace, inspect role
   and terminal pattern, and disclose cancellation/workcount differences.
9. Update SDD/runner wording to every REQUIRED latest generation succeeds, with
   only these predeclared and causally proven victims separately classified.
   Replace draft per-frame cached-oracle/candidate-t2 alternatives with the
   decided one-time post-t3 validation seam. Keep workloads/deadlines/fixed inputs.
