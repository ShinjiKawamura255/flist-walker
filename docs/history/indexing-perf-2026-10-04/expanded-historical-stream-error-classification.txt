Historical stream Err / closed-receiver classification (READ-ONLY)
2026-10-04. Original git-show sources v0.27.0..v0.30.0; current frozen3cf unchanged.
No port/source/test/build/perf changes. Current full stopped after336/616; this inspection does not accept that failure or authorize a relaxed outcome.

All four tags share the following actual behavior.
1. MailboxResponseSink::send returns Err(()) both for Full retry with !request_is_current() and for other mailbox publication errors (Closed / SlotOccupied). It erases the distinction. A Full canceled data send can fail even when mailbox is not physically closed.
2. Walker callback flush failure sets stream_err='index receiver closed' (v27:622, v28/29:630, v30:640). The post-walk latest/shutdown check sets 'superseded' only if stream_err.is_none() (v27:655, v28/29:663, v30:673). Once a flush error exists, current=false does not replace it with superseded. Final flush and truncation-notice send failures also return the receiver-closed string directly.
3. The outer worker Err arm classifies only exact error=='superseded' as Canceled. Every other stream error, including 'index receiver closed', attempts IndexResponse::Failed. It does not recheck request freshness to normalize the error. Thus Warm removal racing a full flush can yield an actual Failed offer with current=false under existing production semantics.
4. Failed/Canceled/Finished offer is distinct from successful publication. Canceled send result is ignored then execution continues; Failed and Finished send failure logs receiver_closed then continues. Worker lifecycle trace 'failed'/'completed' is emitted only after successful corresponding send; Canceled trace is emitted after its ignored send result. No terminal trace or cleanup alone proves delivery/physical return.
5. stream success -> Finished has no additional outer freshness check immediately before the offer. A naturally completed request can therefore race removal and offer Finished; its publication and actual committed generation still need exact existing proof. Genuine I/O errors remain Failed; current=false alone never proves every failure was authorized cancellation.
6. FileList callback/final/replacement flush failures also map to 'index receiver closed' (v27:415/428/500/524; v28/29:+8; v30:+18). Do not treat this error label as a typed actual-Closed witness. Reader/discovery cancellation remains its original separate superseded handling.

Implication for historical comparison / current diagnosis
- Yes, existing Warm-cancellation races can have Failed offers as well as Canceled, and can race a Finished offer. This is present on all four original tags; it is not an absent API or historical unsupported operation.
- Error text 'index receiver closed' does not distinguish actual Closed/SlotOccupied from the freshness-aborted Full retry. A future accepted contract would need the original publication reason plus exact owned invalidation, terminal/closure and physical-return evidence. This memo does not authorize adding a Failed allowance or changing production classification.
- Preserve actual Failed outcome in retained evidence; no performance inference, no failure-to-unsupported reclassification, no whole current worker body backport. Current physical settlement and final latest-generation oracle remain necessary.
