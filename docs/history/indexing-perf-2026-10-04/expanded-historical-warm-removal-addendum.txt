1. Earliest actual invalidation, all four tags
IndexCoordinator::replace_warm_tab is byte-identical across v0.27.0 through v0.30.0.
The first mutation is latest_request_ids.remove(previous_warm), original-tag index_coordinator.rs:528 (v27), :558 (v28/29/30).
It precedes the .filter(request_tabs.contains_key) and superseded_request_ids insertion. Removal can occur even if that filter rejects the removed ID.
A valid scalar witness must come from the actually returned nonzero removed ID and independently match request_tabs[removedID] == previousWarm. Checking contains_key alone is insufficient as a witness; changing the existing production filter to route equality is prohibited.
The fields warm_tab_id, latest_request_ids, request_tabs and superseded_request_ids exist in all four tags. No API absence makes this operation unsupported.
Same-Warm early return, oldWarm=None, mutex-lock failure, missing latest ID, zero ID or missing/wrong route must not produce an authorized removal witness.
promote_warm_tab only changes warm_tab_id. It never removes latest, and must not emit a warm-removal witness.
clear_for_tab_after_reclaim and cleanup_request also remove latest entries (v27 :238/241 and :413; v28+ :268/271 and :443). Those removals do not constitute the typed replace-Warm cause and cannot authorize an unrelated None latest.

2. Minimal cfg(test) scalar seam, subject to approved v2 contract
All four tags can observe oldWarm, replacementWarm (method input), actual removed request ID and the actual request-to-tab route without a production API change.
Opt-in/default-off bounded observation storage with sticky overflow is test-only. Capture owned scalar fields; no payload/Arc pin, queue replacement or production scheduling change.
While latest mutex is held, take the observation clock immediately before the real remove only when observation is enabled and the exact eligible identity is available; record the actual returned removed value. Append the scalar after unlocking. Preserve the original remove/filter/insertion evaluation order and behavior.
Disabled operation must add no observation clock/allocation. Invalid identity, unmatched operation, duplicate witness or sticky overflow fails proof, rather than yielding an unsupported classification.
The coordinator lacks direct Active/root context. Do not populate invented currentActive/root fields or copy current production bodies to older versions. Any future callsite context extension requires separate scope approval.

3. Actual activation and caller-specific order
Normal switch_to_tab_index_at order is shared across all four tags:
try_prepare/preflight -> deactivate old tab -> resource/commit guards -> set_active_tab_index_at(next,now) -> load_tab_payload(next) -> promote_warm_tab OR replace_warm_tab(previous indexing tab) -> activate_background_tab_after_transition -> enforce budget.
replace-Warm call anchors: tabs.rs:1227 v27; :1349 v28/29; :1361 v30.
A rejected/deferred preflight or commit returns without successful replacement/switch completion. Out-of-range and already-Active no-op calls are not a new switch acknowledgment; bind the declared distinct previous/target tabs. retry_pending_tab_activation executes the real switch later; a click/permission timestamp is not an actual switch acknowledgment.
v28+ additionally cancels pending Create FileList work before deactivation, returning deferred if that gate cannot complete. v27 lacks that gate. The fixed indexing-only TabChain does not initiate Create FileList; preserve the real gate if encountered, and report any actual deferred/failure rather than fabricate acknowledgment.
Actual driver acknowledgment is feasible on every tag using actual current_tab_id, shell.runtime.root, pending_activation_tab_id and a clock after successful activation but before dependent refresh. Bind the fixed declared target tab/root/stage and the permitted interval to the exact removed request. Root acknowledgment is not evidence of emitted source or committed membership; those need their independent actual request/source/commit witnesses.
restore_recently_closed_tab uses the opposite order: replace-Warm at tabs.rs:1562 v27 / :1690 v28/29 / :1702 v30, then new Active set/load at :1572/1573, :1700/1701, :1712/1713. Thus a coordinator witness cannot universally imply target Active at removal. Fixed switch proof must not borrow a restoration event.
request_background_index_refresh_for_tab_with_mode also replaces Warm, pipeline.rs:254 v27 / :310 v28 / :311 v29 / :321 v30, before allocating the new request and begin_background_refresh. This is not a tab-switch acknowledgment. Reject unrelated background-refresh witnesses.
v28+ background-refresh differences include CreateFileList pending index ID tracking, PreserveSort mode and complete_walker_snapshot. These do not change the earliest Warm removal. Keep actual historical modes/protocol; do not backport these fields into v27.

4. No-marker paths and terminal roles
preempt_background_for_active_request has the same scheduler decision semantics in all tags: queued Active required and inflight >= 2; prefer non-Warm inactive victim, fallback Warm; replacement is queued ID or zero; equal latest value causes no mutation. INDEX_MAX_CONCURRENT is 2 in each tag.
Warm replacement removal runs independently of dispatch pressure. If cleanup leaves inflight=1, the incoming Active request can dispatch without preempt; if victim cleanup already completed, it need not be a dispatch victim; no queued Active or an already-zero latest also produces no preempt marker. None priorlatest after a genuine Warm removal is plausible; a lone None without its exact earlier cause remains invalid.
MailboxResponseSink::request_is_current uses shutdown plus latest[tab] == request ID on all tags. Real removal alone invalidates the running producer, so Canceled publication/physical return may precede any later preempt marker.
Keep v2 cause vs terminal-role distinction: an ordinary intermediate predecessor may have a genuine Finished race or the strictly authorized closed-receiver path; do not require Canceled globally for every typed mutation. Latest declared B victim uses its specified real Canceled/last-good-seed role; latest A8/C7 still require Finished with actual source/root/commit and independent oracle.
Earliest removal selects the exact owned victim; it cannot certify physical return, t2/t3 or debt settlement. Keep started/removal/terminal-publication/physical-return chronology, actual routing absence, worker/load zero and all-tab debt requirements. Last-good seed must be the exact same tab/root/source/generation and independently validated ordered membership. No predecessor or earlier A5 witness may authorize new A8.
