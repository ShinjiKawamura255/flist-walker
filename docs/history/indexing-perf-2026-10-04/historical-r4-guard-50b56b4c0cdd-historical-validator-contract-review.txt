Decision
r1 status output is sufficient to build a separate fail-closed historical validator for sealed PASS, observed FAIL and explicit NOT_RUN, provided actual adapter compile/guards and command/source identity evidence are accepted first. It is not sufficient to positively classify NON_ELIGIBLE from a panic string. A safe initial validator can retain such cells as FAIL (zero accepted timings) until typed eligibility outcome support is independently authorized; it must not claim distinct NON_ELIGIBLE coverage yet.
No weakening or change to frozen current collector is required. Its one-successful-libtest gate is intentionally preserved for current runs. A separate small historical collector should own only process/status framing, reuse the exact current typed row/victim/ABBA/chronology predicates as reviewed code, and perform aggregation after whole-cell admission. Never feed synthetic successful trailers/exit0 or rewritten per-cell logs to the current collector.

Evidence / source-level gap

FAIL accepted_rows is zero even with prior emitted pairs. A next cell may start only if the previous sealed status proves both positive_cleanup and root_restored. An uncertain cell causes remaining requested cells to emit NOT_RUN without starts. Truncated runner lines251–317 adds uniform start/status, real failure exit, zero accepted partial rows, actual config before/after equality and independent config_restoration_authorized.
historical_perf.rs CellProof::safe lines98–105 includes actual runtimes/parsers and every declared owned writer; writer proof lines78–88 requires exactly one actual handle, first real stop reply, first bounded wait and successful actual join. The status boolean is therefore backed by a source-pinned gate, not inferred from zero queue debt, terminal publication, producer-body return or a requested stop. cleanup_evidence is a Rust Debug string, useful for diagnosis but not a stable JSON proof schema. Do not reverse-engineer Debug formatting/Instant addresses as an independent validator API. Bind boolean attestation to exact accepted source/guard evidence; require its presence as literal true. If independent per-handle reconstruction is wanted later, add a narrowly scoped structured proof event rather than claiming the existing Debug string already provides it.
Gap: driver.rs near1942–1971 derives eligible from actual observed workload but full-mode assert occurs before several subsequent source/primary-terminal/row assertions. runner emits only PASS/FAIL/NOT_RUN; no typed NON_ELIGIBLE status/outcome exists. Parsing “actual operation must overlap” from panic text cannot establish all correctness/required-generation/physical/seed truth and cannot safely reclassify every such failure. This is a classification boundary, not a false-PASS in r1. Generic FAIL is sufficient to retain and exclude first real failures before main diagnoses them.
To promise explicit NON_ELIGIBLE before performance, obtain separate authorization for a minimal typed ineligibility outcome: emitted only after all ordinary correctness/root/source/request/seed/oracle gates have passed, tied to actual case/source/run identity and the exact observed failed eligibility predicate; runner must still seal zero accepted rows and preserve genuine process failure. Missing work, producer panic, timeout, source mismatch, oracle/order corruption and unknown cleanup remain FAIL regardless of adjacent ineligibility. No semantic backport or trace adjustment follows from that label.

Minimum input / process contract
1. Bind original tag commit, original lock/manifest, historical source map, adapter/validator SHA, exact runner test name, command/env/pairs/entry count and separate target to a retained execution sidecar. Rehash the complete original combined log and sidecar. Preserve raw command process exit and actual libtest summary separately; do not infer exit from printed text. Compilation/discovery failure, zero matched tests and a killed/lost process are separate process failures with planned cells NOT_RUN, never NON_ELIGIBLE/unsupported.
2. Require exactly one matching selected libtest invocation and META event. Exactly one actual test is selected. Accept either a genuine success trailer+observed successful process exit, or a genuine FAILED trailer+observed failure exit (e.g. the retained cargo/libtest exit101). A FAILED wrapper is one failed test regardless of how many cells failed. Its failure must be accounted for by sealed FAIL/noneligible/uncertain statuses; all-PASS plus unexpected whole-test failure is not a successful matrix. Unknown exit, absent/duplicate/mismatched trailers, extra tests, or an unexplained fatal outer failure are rejected for accepted timing. Preserve diagnostic evidence rather than forge a completion trailer.
3. Freeze declared requested cells independently from execution META. Cross-check META supported_cells, selected sources/cases, pairs, entries, actual cap/settings, expected_rows and selected-subset/full-coverage label against that selection. For the approved full scale: 44 ordinary +1 separate cap+1 cell/tag,7pairs,14rows/cell,630/tag;180 cells/2520 raw rows across four tags is only a planned full matrix. Missing or failed cells cannot be filled from another run/tag or a control row. A pilot/subset remains explicitly subset evidence.
4. Parse an ordered event stream, not a bag of all SAMPLE lines. Recognize real META/CELL_START/RUN_START/SAMPLE/CELL_STATUS events with strict JSON schema and exact cell keys. A known libtest progress prefix may be handled narrowly for the exact selected runner; arbitrary substring matching must not create an event from panic text. Keep unrelated native warnings as diagnostics. Reject malformed/duplicate event JSON, a SAMPLE outside an active cell, wrong case/source/comparison identity, interleaved cell scopes, and unexpected event order.

Cell state machine / continuation contract
5. Every attempted cell has exactly one START and exactly one terminal STATUS. START matches the next declared cell and exact pairs/entries/expected rows. Active samples bind by comparison and source; case is either B0 or that declared condition name. Run starts, where r1 emits them, identify two untimed warmups and sample pair/position/order; warmups produce no accepted rows. NOT_RUN cells have no START/SAMPLE and explicit reason; missing attempted status is unknown/failure and never a PASS. Cap+1 uses its independent runner/one-cell selection and its own final status; do not require ordinary RUN_START events that cap runner does not emit.
6. PASS admission requires literal positive_cleanup=true, root_restored=true, panic=null, exact actual_partial_rows==accepted_rows==2*pairs, and original row predicates all pass. Truncated additionally requires config_equal_before=true, config_restoration_authorized=true and actual serialized before==after; equality alone grants no authority. Do not accept truthy strings, missing flags, unknown joins or requested Shutdown as cleanup. Status row counts must equal actual log rows within that cell.
7. FAIL admits zero timings regardless of correct=true/eligible=true on earlier partial rows or a complete14-row fragment. Require accepted_rows==0, retain actual_partial_rows and real panic/reason, and keep every raw failed row only in an excluded evidence section. No median/ratio/max from any failed cell enters summaries. A failure with positive_cleanup=true and root_restored=true may be followed by the next START, preserving finite trace and actual runtime behavior; a failure with either false/unknown must end execution: only NOT_RUN statuses may follow. Rows/starts after uncertainty are a protocol failure and invalidate the suspect process. The final failure trailer/exit remains unchanged even when some earlier sealed cells are admitted separately.
8. Future NON_ELIGIBLE is an exclusion status, not a softer PASS: typed actual failed eligibility evidence, all correctness gates positively established, cleanup/restoration flags explicit, accepted_rows=0, and all cell rows excluded. It may continue only after the same physical cleanup+restoration gate. Current r1 has no such emitted status; do not synthesize it from generic FAIL/panic wording. A malformed or unsupported noneligible status is rejected, not defaulted to PASS.
9. Genuinely unsupported declared API/setup cases are separate from attempted runtime failures. Use only source-established/reviewed pre-execution unsupported declarations, preserving that cell's NOT_RUN/unsupported reason and zero rows. Runtime assertion, compile incompatibility, no overlap, timed out worker or failed join never becomes unsupported. Unexpected unsupported metadata under the frozen100k/cap500k full selection is a mismatch to diagnose, not a way to satisfy the matrix count.

Collector parsing can succeed as evidence validation while reporting a mixed/failed benchmark process, but must never print an unqualified “historical benchmark PASS” for such a matrix. “Complete full historical comparison” requires all declared eligible cells and original correct workload proof; missing/failed/noneligible cells remain absent and cannot support faster/slower/regression claims.
