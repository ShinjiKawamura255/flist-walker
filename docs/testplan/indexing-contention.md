# Indexing contention performance checks

TC-228 implements the SP-007/SP-010 measurement contract for NFR-006 through DES-006/DES-009. Use the existing [VM-003 checklist and detail](validation/vm-003.md) alongside the focused checks below. These measurements supplement standalone TC-156/185 search latency; they do not replace it.

## Basic profiles

| Case | Operation |
| --- | --- |
| B0 | Empty query, Score, Files+Folders, Ignore List off, preview off, one active tab; empty initial snapshot |
| S1-selective | At10% ingested set fuzzy `needle`, then hold |
| S1-dense | At10% ingested set fuzzy `item`, then hold |
| S2 | Start empty; at10% ingested set `item`, at25% set `needle`, at50% clear; at most one input per frame |

FileList and explicit Walker sources run separately against actual flat ASCII/Japanese files. The harness removes root `FileList.txt` before Walker timing so both fixtures contain100,000 logical candidates; each source still has its own traversal and batch behavior. Source, logical/emitted/evaluated/match counts and signatures are checked; incomparable sources are not a settings speed comparison. Startup/settings/fixture/oracle generation remain outside the measured request. S1 starts empty so its single fixed input has a nonempty prefix; a t0 query on an empty snapshot can defer all substantive search until index completion and is not this contention trace.

## Commands

From `rust/`:

```sh
cargo test --locked --lib indexing_perf
cargo test --locked --lib worker::search_perf::tests
cargo test --release --locked --lib perf_indexing_contention_paired -- --ignored --nocapture --test-threads=1
cargo test --release --locked --lib perf_indexing_observer_overhead -- --ignored --nocapture --test-threads=1
```

Default heavy profile is100,000 fixture entries,7 pairs, both sources and all three comparisons. Each comparison warms B0 and its case first, then alternates AB/BA. Output lines `INDEX_PERF_META`, `INDEX_PERF_SAMPLE`, and `INDEX_PERF_OBSERVER` contain JSON records. Preserve the full log and nonzero exit status; zero tests or missing/duplicate rows cannot count as successful execution.

`FW_INDEX_PERF_ENTRIES`, `FW_INDEX_PERF_PAIRS`, `FW_INDEX_PERF_CASES`, `FW_INDEX_PERF_SOURCES` select diagnostic runs. Smaller input can finish before search's incremental cadence; a correct small sample may have `contention_eligible=false`. It is not full regression coverage. The default100k contention profile must prove actual nonempty evaluated search overlap, including two substantive requests for S2. Full-profile metadata must match requested case/source/sample counts.

Controls are profile-specific. Identical-condition **AA** pairs measure variability; their ratios do not measure feature cost. **AB** pairs record the operation/settings difference and any extra request/work, including Active+Warm. `F1-ignore-list` enables the fixed `SKIP` term before the measured request in its condition half. `F1-ignore-case` instead starts both halves with Ignore List enabled and case-sensitive matching; its condition changes Ignore Case at10% GUI ingestion, while its control keeps the initial setting. `F1-mid-ignore` starts with Ignore List off and enables it at10% ingestion through the production filter handler, including its refresh. These are distinct operations. Walker Files/Folders AA halves both use the selected kind mask; the100k mixed fixture emits80k files or20k folders respectively. Kind-mask AA ratios measure variability, and historical comparisons require the same mask and emitted work.

The normal extension smoke runs42 GUI condition cells at4096 inputs. Separate tab controls exercise the unchanged half as well; an unmeasured empty companion must remain empty with no allocated index request, whereas seeded or measured companions must match their declared fixture generation. Separate real parser masks and controlled pressure/cleanup guards cover worker-level behavior. These checks establish correctness and finite state transitions; they do not certify100k contention eligibility.

## Evidence and interpretation

Retain compiler/features/locked dependency identity, OS/architecture/CPU and worker settings, fixture/trace identity, frame cadence, source and operation checkpoints. Run heavy measurements sequentially without competing build/perf jobs. Historical tags require separate package target directories; sharing the same package/version target fingerprint can run an obsolete binary. Test-only adapters must not backport scheduling/filter fixes.

Report per-comparison B0 and case median/maximum, all raw paired ratios, and median paired ratio; ratio(case/B0) is feature cost observation, while identical case/settings historical comparisons detect baseline degradation. t1 includes synchronous backpressure and nested work; t2 includes GUI index debt; t3 includes latest results. Producer and GUI overlap are distinct. Stall guards count constructive progress, not retry attempts. Reclaimer-induced pauses and actual search phase counters remain visible.

Basic and truncated t2 report GUI snapshot/debt settlement. The extension driver also requires admitted request bodies and sender load to quiesce, including intentionally revoked work; planned allocations discarded before admission have no worker body and must instead prove their enumerated permission, close and release; compare historical times only within the same identified profile. Worker-only parser timings use their separate consumer-terminal boundary.

Observer on/off uses the same driver, source, cadence and oracle; disabled mode cannot claim t1. RSS and timing ceilings require host-specific calibration before becoming hard gates. Native input and Windows/Linux measurements remain separate evidence axes.

The normal `cargo test` path includes lightweight guards automatically. Its actual-worker entrypoints run as exact, directly owned leaf test processes with known child settings; this isolates process-global configuration writers in unrelated parallel tests. Each child must execute one identified successful test, exit physically and release its owned fixture root. Zero tests, failure, identity mismatch and a bounded watchdog expiration cannot pass. The parent does not change its runtime configuration or environment. Ignored measurement entrypoints retain their explicit serial process and exclude child launch from the timing path. Weekly activation of a new ignored command requires the controlled trusted-policy rollout in [CI_OPERATIONS](../CI_OPERATIONS.md); local implementation alone does not activate that workflow.

## Additional profiles (TC-229–232)

Each extension has its own matched control; basic empty-snapshot B0 cannot substitute for a refresh or committed-Active setup.

Ordinary extension setup verifies an empty committed active snapshot before the measured request. Natural-reclaim and fixed A→B→C→A profiles first seed their declared tabs with real successful100k requests outside timing. Natural reclaim then publishes a distinguishable next generation at the same root. Stable Active-search/Warm-index profiles seed only A100k and acquire B's empty committed snapshot through its own real setup request. The preview profile uses this committed ActiveA100k/empty measured B setup as well, with finite preview selections instead of query edits. Active+Warm and promotion use their specified measured requests and finite switches from empty setup; they do not implicitly receive a100k last-good seed. Preserve these initial-state differences when selecting a historical comparison.

| Family | Work and acceptance |
| --- | --- |
| F1 | Walker Files-only/Folders-only, Ignore List and case sensitivity, a finite mid-index filter edit; S1+ignore and S2+Files-only. FileList GUI locks both kind filters, so parser kind-only work has a separate worker-level profile. |

| R1 | Refresh from an existing snapshot with distinguishable generation membership, including natural reclamation. Controlled reclaimer Full positive/negative guards are separate from naturally observed timing. |

Stable Active/Warm setup creates empty tabs before populating A; creating B from populated A would inherit its committed snapshot and invalidate the workload. The empty B snapshot must be acquired by a real setup request at that same root/source; merely assigning runtime fields to a startup snapshot does not meet the precondition. B's own GUI-admitted progress drives10/25/50% query checkpoints. Producer batches and A's already-complete count cannot drive them. S1 needs actual100k evaluation, and S2 needs at least two distinct substantive100k worker requests while B remains unsettled. Tab switches may defer actual activation. Record requested and activated times; issue a dependent refresh or next switch only after the intended tab is active. Keep the common finite checkpoints and include the wait in measured completion, rather than refreshing the previous tab. A successful B terminal plus request/tab/finalizer/filter/kind/reclaim settlement determines t2; t3 also requires A's latest query/sort oracle. Insufficient genuine overlap remains NON_ELIGIBLE.

A successful kind/sort/preview response dispatched after t0 and delivered before the last confirmed-unsettled indexing checkpoint proves completed concurrent work. Empty-query AllMatches sorting has zero fuzzy evaluation by design; O1 uses the actual nonempty candidate dispatch, matching sort mode/scope/tab/root, the captured request epoch, and a successful owned sort response, while S1/S2 retain their substantive fuzzy-evaluation requirement. A received response can prove the completed worker work even when production has already cleared its active request through sorted-cache reuse; record the route outcome and do not claim that a stale response updated GUI state. That conservative evidence does not measure the worker's CPU phase duration. Pending requests alone do not qualify. Preview checks the final selected path and nonempty expected text.

Intentional filter/tab supersession can close an old mailbox before its worker offers a terminal response. Bookkeeping release is not physical completion. Retain the actual offered terminal, publication failure and revoked request identity, and wait for request-body return; an admitted old closed request cannot satisfy t2 until its worker body returns. A planned allocation never admitted to a worker has no return event; it must be classified separately and prove allocation identity, prior enumerated discard permission, mailbox close and bookkeeping release. Every required latest planned request must finish successfully with the expected source and membership. An unplanned cancellation or a canceled/failed required latest request rejects the sample. A declared victim must have the specifically proven aborted terminal below. A Failed terminal establishes this role only with the exact actual stale Full data-send abort witness; a generic failure cannot. Superseded predecessors retain their existing prior-permission and exact-successor proof, including a closed-receiver failure after an authorized mailbox close. Only the fixed TabChain trace has the separately declared victim role described below. Reconcile request allocation/admission/release records and the exact planned request identities, including requests created and retired within one frame. Observation histories retain only payload-free handles; retaining an obsolete mailbox or entry snapshot would change reclamation timing.

Request tracking treats latest-map0 as a cancellation marker rather than an allocated request. Select only the same tab's maximum owned planned ID with exact allocation/ledger identity. The marker requires prior Warm-eviction permission or a specifically validated observed-Finished cause for that exact owner. A completion flag alone is insufficient. With no live map entry, logical release plus route absence normally preserves identity. Only an exact observed Warm-removal cause bound to the actual acknowledged fixed switch may preserve the current owner's identity while its route/body remains live. Derive this proof in the real driver; a supplied flag or an old owner's event cannot authorize a newer ID. Selection never substitutes for physical completion or t2/t3 correctness.

Fixed A→B→C→A declares its old-Warm candidate before each switch. A bounded, default-disabled event records the actual nonzero latest ID removed by Warm replacement, its matching live route/tab, old/new Warm roles and the mutex-local removal time. Bind that event to the exact declared operation, permission and actual switch acknowledgement: current tab, actual runtime root, no pending activation and time. A deferred activation completed inside a frame must be acknowledged before that same frame's owner selection, completion checks or dependent refresh, without another frame/input. This binding applies only to the fixed switch path; it is not a direct measurement of Active-at-removal and cannot be generalized to background refresh or closed-tab restoration.

In the full100k TabChain trace, if the prospective old-Warm request has an observed data-complete marker, Finished offer or Finished publication, wait for its exact request/root/source/count commit and own debt settlement before declaration and switch. `finished_warm_commit_waits` records stage, owner, requested checkpoint and measured wait start/end; actual switch time remains in the input trace. The wait drives normal16ms frames inside the unchanged30s constructive bound, and is included in endpoints. TC-229 `finished_warm_switch_waits_for_own_commit_before_eviction` covers Finished arriving before admission with an uncommitted seed; `finished_warm_admission_accepts_actual_commit_and_rejects_stale_identity` checks real commit and wrong-generation/debt rejection. The strict Finished/latest and full-oracle negative guards remain unchanged. TC-229 `completion_offer_warm_switch_waits_for_own_commit` covers the offered/unpublished and data-complete boundaries. The small smoke preserves the three real inputs and all request/oracle guards but does not prove full contention or typed abort execution. A standalone Warm removal can invalidate a request even when no later preemption runs.
